# Načrt razvoja aplikacije StudyFlow

## 1. Organizacija razvoja

Razvoj aplikacije StudyFlow poteka v ekipi treh članov. Začetne razvojne naloge so evidentirane kot GitHub Issues, kjer so navedeni opisi nalog, kriteriji sprejema in prioritete.

Trenutno je pripravljenih 12 začetnih nalog, ki pokrivajo glavne funkcionalnosti aplikacije.

Končna razdelitev odgovornosti med člani ekipe še ni določena. Naloge bodo posameznim članom dodeljene po skupnem dogovoru, pri čemer bomo upoštevali zahtevnost nalog, interese članov in enakomerno porazdelitev dela.

Napredek razvoja bomo spremljali prek GitHub Issues, spremembe programske kode pa z uporabo sistema Git.

## 2. Faze razvoja

### Faza 1 – Priprava projekta in uporabniškega vmesnika
- Vzpostavitev osnovne strukture projekta Flutter.
- Implementacija začetnega zaslona.
- Implementacija svetle in temne teme.
- Priprava podatkovnega modela.

### Faza 2 – Osnovne funkcionalnosti
- Implementacija upravljanja predmetov.
- Razvoj tedenskega učnega koledarja.
- Implementacija Pomodoro časovnika.
- Implementacija zaslona za učna gradiva.

### Faza 3 – Integracije in umetna inteligenca
- Integracija Firebase Authentication.
- Vzpostavitev Cloud Firestore.
- Integracija AI modela za analizo gradiva.
- Generiranje kvizov na podlagi učnega gradiva.

### Faza 4 – Spremljanje napredka in prilagajanje
- Implementacija statistike učenja.
- Povezovanje učnih sej s statistiko.
- Zaznavanje premikanja telefona z akcelerometrom.
- Nadaljnji razvoj dinamičnega načrtovanja učenja.

### Faza 5 – Testiranje in zaključek
- Preverjanje delovanja posameznih funkcionalnosti.
- Integracijsko testiranje.
- Odpravljanje napak.
- Priprava končne dokumentacije in predstavitve.

## 3. Prioritete razvoja

Najvišjo prioriteto imajo osnovne funkcionalnosti, ki omogočajo uporabo aplikacije: upravljanje predmetov, učni koledar, Pomodoro časovnik, podatkovni model in uporabniška prijava.

Dodatne funkcionalnosti se razvijajo postopoma, glede na razpoložljiv čas in napredek ekipe.

## 4. Spremljanje napredka

Napredek projekta spremljamo z uporabo GitHub Issues. Naloge se sproti posodabljajo, zaključene naloge pa se označijo kot zaprte.

Spremembe programske kode spremljamo z uporabo Git commitov in po potrebi Pull Requestov.
